# История важных изменений

## 2026-11-12 — фото без премиума: размытая копия получателю (ветка `loop/photo-blur`, не выкачено)

Отправлять фото может любой пользователь. Живой получатель без премиума получает событие `media` с `locked=true` и размытой копией (JPEG ≤480 px, без EXIF), оригинал и `tg_file_id` ему не уходят; без байтов или при сбое копии фото пропускается (в истории `skipped`), а фото только по file_id отправителю отвечается 204, как при успехе: отправитель ничего не видит (`forward_media` возвращает `locked`). Видео, кружок и голос гейтятся как прежде. Боты и Worker должны показывать блюр и предложение премиума по `locked`.

## 2026-11-12 — «Пошлый чат»: премиум-режим 18+ (ветка `feat/adult-chat`, не выкачено)

`POST /peers/{platform}/{bot_key}/{user_id}/search` принимает необязательное тело `{"mode": "normal"|"adult"}` (без тела — normal, неверный режим — 422). adult требует активного премиума, иначе 403 `{"detail": "Пошлый чат доступен только с премиумом"}` (слово «премиум» — по нему боты показывают предложение купить). Очередь делится по режимам (`chat_sessions.mode`, `008_adult_mode.sql`): люди и аккаунты chat-engine соединяются только внутри режима. `/engine/demand` дополнен `modes`, `/engine/{account}/hunt` принимает `{"mode"}`, attach берёт ждущего человека режима аккаунта; engine_bridge читает `mode` из `GET /accounts` chat-engine и охотится по режимам раздельно. Жалоба ищет заново в режиме диалога; «Следующий» бот вызывает `/search` сам и обязан передать режим. Причина: просьба пользователя о премиум-режиме, аккаунт `spec1` обслуживает adult.

## 2026-11-12 — промо «купи премиум» на 5-м, 15-м, 25-м… диалоге (ветка `loop/promo-every-10`, не выкачено)

Колонка `bot_users.dialogs_ended` (`007_dialogs_ended.sql`, счёт с нуля) растёт при закрытии диалога у каждого человека; `set_idle`/`set_searching` возвращают `DialogEnd`. Если счётчик `% 10 == 5`, платформа vk/tg и нет активного премиума, брошенному в `partner_left` приходит `promo: true`, а инициатору `/stop` — `StopOut.promo: true`. Отдельного события `promo`, задержки и `ChatService.aclose()` нет. Промо не получают инициатор поиска/«Следующий», «украденный» у chat-engine и недоступный при `delivery_failed`. Причина: просьба пользователя о предложении премиума; решение по доработке — флаг вместо отложенного события. Клиентская часть — в dating-bot-vk и dating-bot-tg.

## 2026-11-11 — engine_bridge: failover при лимите аккаунта (ветка `loop/engine-limit-failover`)

Мост понимает состояние chat-engine `limited` (и `limited_until` в `/accounts`): снимает hunting в Chat API без остановки в engine, не берёт такой аккаунт в поиск и переходит на другой свободный; при 409 на start аккаунт отдыхает 60 с. Работает и со старым chat-engine (поля нет). Добавлены тесты `engine_bridge/tests/`. Не выкачено до релиза вместе с chat-engine. Причина: упёрлись в лимит аккаунта, люди зависали в поиске.

## 2026-11-10 — история диалогов (ветка `loop/dialog-history`)

Все реплики пользователей во всех каналах пишутся в Postgres (`dialogs`, `messages`): диалог открывается при образовании пары и закрывается с причиной и стороной, ушедшей из чата. Реплики старше 90 дней раз в сутки выгружаются в бакет медиа (`archive/messages/ГГГГ/ММ/ДД.jsonl.gz`) и удаляются из базы только после проверки загрузки. Причина: пользователь потребовал хранить все диалоги (вариант «Postgres + архив в S3»). Сбой записи не мешает доставке. Чтения истории нет; политику конфиденциальности нужно обновить отдельно.

## 2026-11-10 — напоминания давно не заходившим (ветка `loop/reminders`)

Фоновая задача `reminders` в lifespan Chat API раз в 15 минут ставит в рассылку (`publish_notices`, VK/TG боты и онлайн-гости сайта) текст из `reminders/content.py` людям, которые не появлялись в чате 24 ч–30 дн, не в поиске/диалоге, без напоминания за последние 24 ч и вне тихих часов 23:00–10:00 МСК. Параметры только в коде (`reminders/settings.py`), не в `.env`; выпущено выключенным (`ENABLED=False`). Новая таблица `reminder_log` (аддитивно, `001_schema.sql`). Причина: просьба пользователя о ежедневном напоминании после последнего действия. Для включения нужны правка `ENABLED`, финальный текст/фото и деплой.

Добавлены `storage` (supabase/storage-api v1.74.0), `storage-gw` (nginx 1.27-alpine, `/storage/v1/*` для Studio), `media-migrate` (rclone 1.69.1, профиль migrate; теперь только создаёт бакет), `003_storage_roles.sql` (роли postgres/anon/authenticated/service_role/supabase_storage_admin, права на схему storage). `deploy/update.sh`: ключи `STORAGE_S3_*`, свои `JWT_SECRET`/`ANON_KEY`/`SERVICE_ROLE_KEY`, бакет до переключения chat-api, smoke, таймауты на всех сетевых шагах. Первый боевой деплой с переносом из Beget завис (`rclone size` ~24 мин, Beget недоступен) и был откачен; повтор без переноса: старые медиа не переносятся, для их `media_id` API отдаёт 502, новые загрузки работают. Проверено в Docker (свежий том и повторный прогон шагов деплоя).
